## 4. 遇到的问题

**根因（v1 遗留，本次修正对象）**：v1 改对了 `parameters.ids` 半段，却保留了 `.model` 这一跳。
框架 CubismModel 无公开 `model` 访问器（内部字段 `_model` 为 private），唯一公开途径是 `getModel()` 方法。
故 `.model` 恒为 undefined、`?.ids` 静默短路返回 `[]`，面板参数/部件区永远空且不抛错——**静默失败**是最难发现的一类。

**v1 测试为何全绿仍坏**：v1 附录 A 的假核心把 `model:` 属性焊进形状，等于用错误形状去验证错误代码，双向自洽。
这是「假模型必须镜像真实结构」这条原则的正面案例：假模型形状错，测试即形同虚设。

**本次反向验证**：把 `ids()` 改回 v1 的 `.model` 路径后 L2 层立刻红（node --test 失败，退出码 1）。
证明新测试确实能抓住此根因，非空跑；随后已还原。

**无阻塞**：本轮未遇失败尝试，无卡点，未触发 3 次上限。

## 5. 改进建议

**规格书应标注被废弃的路径**：v1 §0 把 `coreModel.model` 称为「本仓库已有先例」，实为从未执行的死兜底。
建议规格书引用「先例」时必须附该行号是否在生产路径上执行，否则引导后人照抄死代码。
**假模型形状应写成显式契约**：建议规格书要求假模型附「不得含哪些属性」的反断言（本次用例 2 已补）。
仅靠「包含正确字段」无法发现假模型多带了错误字段——v1 正是栽在这里。
**静默失败需显式兜底**：`?.` 链让路径错误退化为空数组而非报错，调试成本极高。
建议此类「取库内部结构」的代码在取不到时 `console.warn` 一次，把静默失败转为可见失败。
**勘误机制运转良好**：v2 §6 的勘误表把 v1 三处错误逐条定位到行，使本轮修正无需重新排查。
建议后续每轮修正都保留此表，并注明「不回写前版规格书」的约定。
**遗留死代码待清理**：`l2d.ts:944-945` 的 `.model?.canvasinfo` 兜底永不执行，v2 §6 已列为范围外。
建议下阶段一并处理（改 `getModel()` 或直接删），否则它会继续充当「先例」误导后人。
