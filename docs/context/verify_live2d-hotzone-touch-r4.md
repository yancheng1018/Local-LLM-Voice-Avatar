## 0. 定案结论（症状②）

**根因**：`clampChain` 的 `Math.abs()` 把负增量翻正（`l2d_params.ts:52-56`）。
**决定性证据**（r4 §10.4.2，可复现 §9-C ⑦）：把本地引擎逐字复刻后模拟，
`wuqi_3 TouchDrag6` 的**向上拖与向下拖产生逐点完全相同的数值**：

```
向上拖: 15px=1.50  30px=3.00  45px=4.50  60px=6.00  ...  120px=12.00
向下拖: 15px=1.50  30px=3.00  45px=4.50  60px=6.00  ...  120px=12.00
```

**两个相反方向的输入产生同一个单调递增的输出** → 用户感知即"方向跑"。

**你提供的三条反馈怎样锁定了它**：

| 你的反馈 | 作用 |
|---------|------|
| **「目测均匀变化」** | ✅ 吻合：`abs()` 后数值线性单调增长，**看起来完全正常**，所以只会觉得"方向不对" |
| **「还没到区域外就开始方向跑了」** | ✅ **决定性**：异常从第一帧就发生（15px 就已是 1.50）。若机制是"出区后轴翻转"，异常应始于出区瞬间——**你明确说"还没出区"，排除轴翻转** |
| **`touch_drag7=180.0`** | ✅ 对照组：drag7 的 `rangeAbs=0`（不取绝对值），所以**保号、方向正确**，与 l2d.su 一致 |

**⇒ `drag6` 与 `drag7` 唯一字段差异 = `rangeAbs`（1 vs 0）**：一个错、一个对。

## 1. 症状②已完整结案（无遗留歧义）

**用户第三轮澄清 + 精确复测**：

> 「我所说的最上方 0 / 最下方 30 指的是**模型中滑块所处位置**时对应的数值，**并非鼠标所处位置**。」
> 「鼠标从中间拉到**最上方**时**滑块反向跑到最下方，数值为 30**；
> 鼠标从中间拉到**最下方**时**滑块正常跑到最下方，数值为 30**。」

**⇒ 读数口径澄清后（`最上方/最下方` = 滑块位置，非鼠标位置），观测从"疑似反证"转为"完美确证"。**

| 操作 | 站点期望 | **本地实测** | 结论 |
|------|---------|-------------|------|
| 鼠标从中间**向上**拉 | 值**减小**（滑块上行） | 值增到 **30**，滑块**下行** | **反向** ← `abs()` 翻正 |
| 鼠标从中间**向下**拉 | 值**增大**（滑块下行） | 值增到 **30**，滑块**下行** | **正常** |

**⇒ 两个相反方向给出同一结果（值=30）→ 一个显"正常"、一个显"反向"。**

**模拟逐点复现**（r4 §9-C ⑦-2，`wuqi_3 TouchDrag6`）：

| 累计位移 | 向上拖 | 向下拖 |
|---------|-------|-------|
| 30px | 3.0 | 3.0 |
| 150px | 15.0 | 15.0 |
| **300px** | **30.0（钳上限）** | **30.0（钳上限）** |

**两方向逐点相同、且都饱和到上限 30** —— 与你的实测**完全一致**。

> 拖得短也一样：拖 100px 两方向都得约 10。**无论拖多远，上/下结果总相同** = 症状②核心特征。

**⇒ 症状② 根因确认：`clampChain` 的 `Math.abs()` 抹掉符号（`l2d_params.ts:52-56`）。**
**⇒ 可推进的修复：恢复 `dragDirect` 门控**（站点三步链次序 `dragDirect → rangeAbs → range`，
会把负值归零，与站点一致；不影响 `rangeAbs=0` 的规则如 drag7）。

## 2. 症状①（维持待修）

**根因**：`isRuleInteractive`（`l2d.ts:299-300`）的
`ATA.idle !== chainIdleIndex() → 拒` 与站点语义**方向相反**
（站点是 `ata.idle === idleIndex → 拒`，用于**防重复播同一 idle**）。
**站点源码直证**（r4 §4.3），未受本轮反馈影响。

**你的观测（清空后 wuqi 仅 1 个 G 区）是对的**，原因已定位：
`touchZoneStates`（`l2d.ts:462-484`）判定顺序 **`H` → `G` → `T` → `O` → `ok`**，
`H`（不可见）在最前 → 大量 gated 区当前**不可见，判 `H`**，走不到 `G` 分支。
**它们同样点不到**，只是不显示为 G。

⇒ **「G 区数」不是症状①的完整口径**：可感知面 = `G` + `H` + `O` + `T` 的并集。

## 3. 「调试栏不刷新」= 本地 bug（已定位）

**不是你的操作问题，也不是站点那种 bug**，是 `l2d_debug_panel.ts:132-135` 的事件监听缺陷：

```ts
input.addEventListener('pointerdown', () => this.active.add(key));   // 压下 → 标记"活跃"
for (const ev of ['pointerup','pointercancel','blur']) {
  input.addEventListener(ev, () => this.active.delete(key));         // 释放 → 解除标记
}
// 151 行：if (this.active.has(r.key)) continue;   // "活跃"行跳过回写
```

`pointerup` 挂在**滑条自己**身上。你按下后把鼠标**移出滑条再松开** → `pointerup` 落在别处 →
**input 收不到 → 该行永久卡住不刷新**。**只有关开面板或换模型才清空。**

**⇒ 恢复：把「🧪 调试栏」关掉再打开。**
**⇒ 修复候选**（另开任务）：`pointerup` 应挂 `window`/`document`，或用 `setPointerCapture`。
